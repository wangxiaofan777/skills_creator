## 错误处理(Go 重点)

| 规则 | 问题与修法 | 风险 |
|---|---|---|
| 忽略 error 返回值(`_ = f()` 或直接丢弃) | 接住并处理/上抛/记日志 | 🔴 失败分支是新行为,需确认期望 |
| `if err != nil {}` 空块 | 补处理逻辑 | 🔴 同上 |
| panic 用于普通错误流 | 改返回 error | 🔴 调用方需同步处理 |
| errors.New(fmt.Sprintf(...)) | 改 fmt.Errorf,需要包装时用 %w | 🟢;改 %w 后 errors.Is/As 行为增强 → 🟡 |

## Go 项目特别注意

- goroutine 泄漏与 channel 死锁类问题 Sonar 检出有限,review 时主动看:每个 `go func` 是否有退出路径、channel 是否可能无人收发。
- defer 在循环内(资源延迟到函数结束才释放):提取函数包裹 → 🟡,释放时机提前。
- context 缺失/未传递:补 context 是 API 变更 → 🔴。
