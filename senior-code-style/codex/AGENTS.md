# AGENTS.md — 资深代码风格(根)

目标:代码像工作十年以上的人写的——**平、直、少跳转,抽象只在真正赚到时出现**。前端"组件/hook 过度拆分"与后端"反复套方法"是同一个病。

## 先探测,别假设栈
动手前读 `pom.xml`/`build.gradle`(后端)与 `package.json`/`tsconfig.json`(前端),认出实际用的框架与库;抽样读几个既有源文件学本地约定。**匹配既有约定优先于套用本文件的偏好。**

## 第一原则:抽象必须"配得上"自己的存在
方法/类/组件/hook 存在须满足之一,否则内联:① 真被复用(2 处以上);② 给不直观操作命名;③ 把确实复杂的逻辑降到可读。
- 三次法则:同一段逻辑出现第 3 次再抽。
- 错误抽象比重复贵;就近原则;不写"包装的包装"。

## 不为平台已有能力引入依赖
- 后端:`List.of`/`String.join`/`Optional`/`Stream`/`record` 已有,别为这些拉 Guava/Hutool。
- 前端:`?.`/`??`/`Array.includes`/`structuredClone`/`Intl` 已有,别为这些拉 lodash/大型日期库。

## 派生而非同步(两端最高频的过度复杂)
能算出来的值当场算,别另存再手动同步。前端用 `computed`/渲染派生,不要 `useEffect`/`watch` 同步可派生状态;后端少冗余字段。

## 其余
守卫语句代替深层嵌套;命名表达意图;注释解释"为什么";不留死代码;一个方法/组件做一件逻辑完整的事。

## 分层
- 后端模块的具体库习惯见该目录下的 `AGENTS.md`(MyBatis Plus / Lombok / Guava / MapStruct / Hutool / Spring / 缓存)。
- 前端目录的具体习惯见该目录下的 `AGENTS.md`(React / Vue / TS / 状态 / 样式 / 数据请求)。
> Codex 按目录就近加载最近的 AGENTS.md,请把下面 backend/ 与 frontend/ 的 AGENTS.md 放进你项目真实的后端、前端目录里。
