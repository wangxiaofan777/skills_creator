## 项目名称
代码合规守卫 SonarGuard

## 一句话简介(5–50 字,此版 38 字)
在 AI 写代码和 git 提交前，自动对照 SonarQube 规范拦截问题并生成可分享报告

## 赛道 / 场景
研发提效 / 代码质量左移

## 标签
Agent, MCP

## 使用的百智能力
开放 API

## 解决的问题
团队代码（尤其 AI 生成的代码）常常违反 SonarQube 规范，却要等到上线前 CI 扫描才暴露——发现晚、改起来贵、还卡发布节奏。开发当下没有人主动查，质量门禁形同事后审判。痛点有三：

1. 问题暴露太晚：写完到 CI 之间是真空期，AI 生成的代码尤其容易埋雷。
2. 修复有风险：开发者不清楚某条 Sonar 规则该怎么修、会不会把功能改坏。
3. 接入成本高：传统方案要装插件、连服务器，Sonar 一挂全员没法提交。

## 方案说明
SonarGuard 是一个“两阶段 + 多端统一”的代码合规守卫：

- 开发阶段（对话内）：在 Claude Code / Cursor / Codex 里，每次写完/改完代码自动对照项目的 Sonar 规则审查本次变更，直接给出“有什么问题 → 怎么修 → 修复有没有风险”。
- 提交阶段（pre-commit 钩子）：git commit 时自动检查暂存区文件，按配置拦截或仅警告。

如何用「开放 API」：通过 SonarQube 开放 API 拉取项目质量配置的活跃规则与文件现存 issue，使报告基于该项目的真实规则而非通用猜测；服务器不可达时自动降级到内置离线规则子集，保证可用。

报告由脚本确定性生成（md / html / json 三种格式，默认 md，落盘到 .sonarguard/reports/ 带时间戳，HTML 自动浏览器打开），并可用 /sonar-scan 命令一键在对话框出报告。

## 项目亮点
- 零依赖：仅用 Python 标准库，pre-commit 秒级；Sonar 挂了 3 秒超时即降级离线，绝不卡住全员提交。
- 三端统一：同一套规则与工作流覆盖 Claude Code、Cursor、Codex，装一次全员受益。
- 报告不靠 AI 心情：脚本确定性输出 md/html/json + 截断规则，/sonar-scan 一键进对话框，AI 只负责叠加修复建议。
- 修复带风险分级：每条问题给 🟢低 / 🟡中 / 🔴高 风险评估，高风险先征求确认，不盲目改。
- 安全：个人 token 永不写入仓库、不在报告中回显。

## 商业价值 / 落地场景
质量左移、研发提效：把“上线前救火”变成“提交前拦截”，显著减少 CI 退回与返工。

落地场景：
1. 团队在业务仓库装一次 pre-commit，全员提交即受检；
2. AI 辅助开发时实时合规审查，治理 AI 生成代码的隐性债务；
3. /sonar-scan 一键生成可分享的 HTML/MD 报告，丢进 MR、工单或团队 wiki 做评审与留痕。

适用于有 SonarQube 的中大型研发团队，接入成本极低。

## 完整项目介绍
**架构**

```
sonar_api.py（标准库，封装 SonarQube 开放 API，输出 JSON 机器契约）
  → scan.py（友好入口，--format md/html/json，渲染 + 落盘 + 自动打开）
  → check_staged.py（pre-commit 钩子，彩色拦截/警告，3s 超时降级离线）
  → render.py（零依赖 md/html 渲染 + 确定性截断）
  → /sonar-scan（slash 命令，一键在对话框出报告）
```

**流程**：探测项目状态(ok/离线) → 拉取规则与存量 issue → 逐文件审查变更 → 出报告 → 按风险分级修复。

**特点**：服务器模式用真实项目规则，离线模式用内置高置信度启发式（空 catch、字符串 ==、硬编码密钥、debugger 等），支持 Java / Python / JS·TS / Go。

**后续计划**：扩充语言与规则覆盖、报告历史清理策略、与更多 CI/IM 集成。
